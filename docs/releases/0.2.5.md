# Tunera 0.2.5 preview — Concert A input

Android package `app.tunera.mobile`, versionCode **8**, following the 0.2.4 preview's code 7. This preview fixes editable numeric settings while retaining the tested live-tuning optimizations.

## Changes

- Concert A can be cleared and retyped without snapping to 390 Hz.
- Both Concert A entry points show decimal keyboards and accept dot/comma decimals.
- Incomplete, malformed, nonfinite, and out-of-range input stays local; complete valid values apply immediately.
- Blur/Done restores canonical display. Closing Pitch setup preserves accepted edits, including when the native field does not emit a blur event.
- No DSP, audio-capture, dependency, permission, or stored-data migration changes.
- Concert A defaults to 440 Hz for fresh installs, reset, and missing/malformed reference values. Existing explicit saved reference pitches remain unchanged; the already-correct runtime default is covered by dedicated regression tests.

## Build and verification requirements

Use the existing local Android toolchain, all four existing APK architectures, and the previous release's signing identity. Independently compare the completed APK against the actual 0.2.4 preview APK certificate and confirm versionCode increases to 8. Do not uninstall or clear application data to work around an update failure.

The existing shared Android Debug certificate SHA-256 is `fac61745dc0903786fb9ede62a962b399f7348f0bb6f899b8332667591033b9c`. It preserves preview update compatibility; it is not production-strength app-store signing.

Run TypeScript, ESLint, the full JavaScript suite, native unit tests, an all-ABI release build and release lint, then verify signature, ZIP integrity/alignment, ELF page layout, actual permissions, package/version, bundled JavaScript, and source provenance. Record final results and artifact checksums with the release.

Host/component tests do not verify an actual Android keyboard/IME, microphone, device lifecycle, responsiveness, battery use, or thermals. Static 16 KB alignment checks are not a 16 KB device runtime test. Publish this as a test preview with those limits visible. No paid build service or GitHub Actions run is authorized for this release.

## Additional Android lint findings

The all-ABI release build and its fatal-only `lintVitalRelease` check pass. The broader `lintRelease` check reports two errors and 40 warnings: the generated splash style uses the API 33 `windowSplashScreenBehavior` attribute while minSdk is 29, and the audio dependency contains notification code without a declared `POST_NOTIFICATIONS` permission. Both error conditions are unchanged from the actual 0.2.4 preview: the complete resource table and the DEX containing `AudioNotificationManager` are byte-identical, and the permission list is identical. App notifications/background audio are disabled. No checks were suppressed and no permissions were added. These are disclosed existing full-lint failures, not a clean full-lint result or a claim of older-device runtime validation.
